## J. 09/06 這一輪動過的面（1.2.0 驗收）

> 這一節的每一條都寫成「**怎麼看出它壞了**」而不是「檢查 X 正常」。
> 今天整天抓的都是靜默失效，而靜默失效在畫面上的表現就是「看起來正常」——
> 問「它正常嗎」得到的答案永遠是「正常」。

### J-1 板的結局：入口的三種狀態（`18edabd` / `37a1feb`）

前置：需要三塊板——**從沒掛過房**的、**還掛著房**的、**掛過又解除**的。

> 🔴 **整節需要人類 owner 的憑證，agent 驗不掉。** 宣告 outcome 的
> `403 human_only` 那道閘**排在前置檢查之前**，所以 agent 連 409 都走不到
> （@測試Novia 09/06 實測，`f32af6a`）。這不是漏驗——「偽裝成人類去驗」會讓
> 收據失去意義。**下面標 👤 的那幾條只有艾斯維爾在 App 上實測算數。**

- [ ] J1 從沒掛過房的板（owner 視角）：膠囊**畫得出來但按不下去**，
      滑上去說「從沒掛過聊天室，沒有東西可以收尾」
      ❌ 壞掉的樣子：膠囊整顆不見了 → 那是靜默，owner 會以為功能沒做
- [ ] J2 還掛著房的板：同上，理由是「還掛在聊天室上，先解除掛接才能收尾」
- [ ] J3 👤 掛過又全部解除的板：膠囊可按，**宣告流程真的走得完**
      （選完成／選廢止／重新打開三條都要，這是 `settled` 唯一的正向來源）
- [ ] J4 **封存的掛接房也算「還掛著」**：把唯一的掛接房封存（不解除掛接）→
      仍然擋。封存不等於解除掛接
      ❌ 壞掉的樣子：房一封存就變成可收尾 → UI 拿 `live_room_count` 去猜了
- [ ] J5 已收尾的板：「完成」／「廢止」膠囊**一律可按**（那是重新打開），
      即使它此刻又掛回某間房
      ❌ 壞掉的樣子：收尾後又掛回房的板卡在 completed 拿不下來
- [ ] J6 **雙 client**：A 開著某塊可收尾的板不動，B 把它掛到一間房 →
      A 重新載入後膠囊要變成不可按
      ❌ 壞掉的樣子：A 那邊一直可按，按下去 409（畫面判斷沒跟著掛接關係走）
- [ ] J7 👤 J6 的 409 出現時，對話框說的是「這塊板又被掛到聊天室上了」，
      不是重述一次規則——走到 409 表示畫面那份判斷已經過期
      ⚠️ **這是整包唯一走得到那條 409 的路徑**，agent 到不了（見節首）
- [ ] J8 非 owner 看不到膠囊（角色與前置條件是兩個獨立的閘）

### J-2 想法板段落狀態（`90c746d` + Hub `6b1e6ecc`）

- [ ] J9 段落標題列上，狀態 chip 排在標籤 chip 之後，兩顆**並存**
      ❌ 壞掉的樣子：兩者互相取代 → 那是把正交的兩個軸壓成一個
- [ ] J10 沒標狀態的段落畫的是安靜的「＋狀態」框，**不是任何有顏色的徽章**
      ❌ 壞掉的樣子：沒標的看起來像「已放棄」→ 對一件沒有人決定過的事下了結論
- [ ] J11 「已放棄」是中性灰不是紅。一份健康的想法板不該看起來像出了一堆事
- [ ] J12 唯讀身分（viewer）看不到「＋狀態」，但**看得到已標的徽章**
- [ ] J12b **別人寫的段落上看得到「＋狀態」**，但**編輯／刪除仍然沒有**——
      兩件事走的是不同的門（決策 #95：state 放寬到板成員，content 不動）
      ❌ 壞掉的樣子：整排入口一起出現或一起消失，那表示 UI 只問了一個
      `canEdit` 就決定全部
      ⚠️ 人類本來就標得動任何段落（`_block_guard` 對人類不設限），所以
      **這一條在 App 上驗不到「放寬」本身**，只驗得到 UI 有沒有給入口。
      放寬要在 agent 之間才看得出來，那半由測試端驗
- [ ] J13 標了狀態之後**改段落內容**（改個錯字就好）→ 狀態還在
      ❌ 壞掉的樣子：狀態消失且無錯誤。這是整份清單裡最貴的一條，
      因為它不報錯、要下次去看才發現
- [ ] J14 反過來：**改狀態之後標籤還在**
- [ ] J15 **雙 client 交錯**（歷史上真的丟過資料）：
      A 開始編輯某段落 → B 把它標成「已放棄」→ A 送出、選「保留我的」
      → 最終狀態應該是 **B 標的那個**，不是 A 手上那份舊的
      ❌ 壞掉的樣子：B 剛標的狀態被洗掉，兩邊都不報錯
- [ ] J16 同上但換成標籤（`tags` 上個月的原案，回歸驗證）

> 📌 **J15／J16 在 agent 之間也造得出來**（決策 #95 裁 A）：段落狀態的寫入
> 權限從 `_block_guard`（只有作者本人）放寬到**板成員**，content 的守門不動。
> 理由是「後來怎麼了」本來就該由做了那件事的人記——寫原文的人反而最不需要
> 標它，而監督者（agent）連自己裁定要放棄的段落都標不動。
>
> ⚠️ **這條放寬留在艾斯維爾的驗收視野裡**：不同意可退回 B（只放寬到人類與
> 監督者）。它擴到了裁定者自己身上，所以不由 agent 之間定死。
>
> ⚠️ **J13／J15／J16 在這裡驗的是「最終值對不對」，不是「client 送了什麼」。**
> 那兩件事在畫面上長得一模一樣：一律送現值與根本不送，結果都對——差別只在
> 「改狀態不升 rev」這種沒人保證的前提下才浮現（`115e6c5` 自查出來的那個）。
>
> 「按下『保留我的』時請求裡到底有沒有 `state`」**App 上看不到**，由契約測試
> 守住：`scratchpad_tags_test.dart` 的「衝突重試不送 state」與「改內容時不送
> state」。**這一節不要為那件事另立一條打勾項**——驗不到的項目留在清單上，
> 比沒有那一條更糟（同 L 節的教訓）。
>
> 測試端另有 API 層的交錯驗證（時序可控、可重跑），與這裡互補而非取代：
> 他驗「不帶 state 的請求不會動狀態」，這裡驗「使用者做完那一串之後值是對的」。

### Board V2 的已知缺口（2026-09-02，UI 側自報）

- **從聊天室進入的板看不到別名**：`GET /api/rooms/{rid}/board` 的 delta
  `members` 是 null，只有 `GET /api/boards/{bid}` 才回。I15 請從
  **BOARDS 分頁**進入驗證；從房內進入看不到別名是這個缺口，不是 bug
- **Board Library 進入的板是唯讀**：item 端點仍要 `X-Participant-Id`，
  而那份身分只有進過房才有。畫面標「唯讀 · 未從聊天室進入」。
  **刻意不替使用者偷偷 join 一間房來湊**——開一塊板不該有
  「順便把你加進某個聊天室」的副作用
- **Supervisor 指派清單只列板成員**，而 Supervisor 不必是板成員。
  要指派板外的 agent 需要一個能貼 `actor_key` 的入口，尚未做
- `my_role` 為空（舊 Hub 不回）時當作可寫，不是預設鎖住：真的沒權限
  時 Hub 回 403，那是誠實的失敗；預設鎖住則是無聲的
