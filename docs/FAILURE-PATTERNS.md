# 失效形狀：靜默失效與它的鏡像

> 本文件是 2026-08-29 一整天跨裝置協作的沉澱。當天在 Hub、bridge、watcher、
> App、隧道五個層面各撞到同一個形狀的問題，值得當診斷透鏡反覆使用。

## 主形狀：看起來成功，實際掛在錯的地方，全程零錯誤

| 案例 | 表面 | 實際 |
|---|---|---|
| session key 分裂 | watcher 活著、沒報錯 | 頂著錯的身分去問，永遠問不到 |
| cloudflared 憑證污染 | 網址印出來了 | 隧道掛在別人的憑證上 |
| 殭屍 participant | 房裡有這個人 | 永遠不會醒，還吃掉 @mention |
| 定向問題推不到人 | 訂閱成功、問題建立成功 | server 那條訂閱是匿名的 |
| Codex 收不到本機人類的 @ | 通知系統運作正常 | 那則被「不通知自己」濾掉了 |

共通點：**每一個都不會拋出錯誤**。它們只能靠「有人實際去撞」才會現形，
而且撞到的人第一反應通常是懷疑網路、懷疑對方、懷疑版本——很少會懷疑
「成功訊息本身是假的」。

### 診斷提示

1. **「沒報錯」不是證據。** 驗收要有正向證據：看到 `session_key=`、看到事件、
   看到 join 回傳的 id。清單上每一項都要能指出「我看到了什麼」。
2. **同一台機器上看不出來的東西，需要處於不同狀態的環境去撞。** 持有 repo
   的那台永遠是「已裝好且正確」的狀態，看不到新機、舊設定、執行中進程。
   跨裝置實測的價值不可替代。
3. **凡是 `if (!x) return;` 的分支都要問「這在別人的環境裡是不是常態」。**
   靠 window bridge、環境變數、本機檔案溝通的模組之間有隱形依賴，型別系統
   看不見它們。

## 鏡像形狀：假的失敗

第五個案例方向相反，但代價一樣：

> 隧道自檢紅燈 → 判定 Cloudflare 速率限制 → 白等十幾分鐘冷卻 → 回頭查一個
> 不存在的問題。實際上隧道從外部完全正常，是**驗證方法**錯了（從 origin
> 本機打自己的公網網址，會被 hairpin、DNS 族別偏好、本機代理打斷）。

假的失敗容易被當成「保守一點沒差」，但它讓人關掉能用的東西、去修不存在的
問題。它的成因幾乎總是同一個：

> **驗證器斷言了超出它觀測範圍的事。**

`❌ 隧道沒有接到本機 Hub` 是一個它證明不了的斷言——它只知道「我這台打不通」。
同一個毛病也出現在 watcher 的舊訊息 `state 無 display_name（尚未 join？）`：
分裂時 bridge 確實 join 成功了，照那句提示去查的人會確認「有 join 啊」然後卡死。

📌 **把「我觀察不到」寫成「事實不存在」，是錯誤訊息最貴的一種寫法。**

修法通常只是措辭：說「本機自檢未通過，可能是本機網路環境所致，請由外部確認」
而不是「隧道壞了」。成本最低，收益最大。

📌 **驗證器本身也需要被驗證。**

## 錯誤訊息的判準

當天品質最高的錯誤訊息有一個共同點：**它們告訴你下一步做什麼，而不只是
「發生了什麼」**。

- ❌ `請指定 target` → ✅ `房裡有多位人類（Bernie、Bernie-2），請指定要問誰`
- ❌ `身分已失效，請重新加入` → ✅ 被踢時明講**不要**再自己加回去（那是人為
  決定，agent 照著「請重新加入」做就等於用工具推翻它），閒置移除時才說可以回來
- ❌ `找不到成員` → ✅ 附上房內目前的名字清單

📌 **同一個狀態碼底下，處置不同的情況就該有不同的 code。** 把它們壓成一個，
等於逼呼叫端去比對人類可讀的中文訊息——而那會在改一個字的時候無聲失效。

## 協作面的兩個約定

**多通道問題。** Hub 是共同真相來源，但不是唯一的指令通道。使用者在私人對話
裡推翻了房裡講定的事，房裡看不出任何異常，而 agent 的推論鏈會在不知情的
狀況下失效。

> 判準：**這件事會不會讓對方的推論鏈失效**。會的話，收到指示的一方負責在
> 房裡補一則說明。

**共用工作目錄。** 兩個 agent 在同一個 working tree 上並行時，`git add -A`
會把對方進行中的變更一起 commit 進去。約定：commit 一律指名檔案，開工前在
房裡宣告要動哪些檔。

## 一個操作教訓

用「不符合某特徵」挑選要終止的進程是危險的：

```powershell
# 意圖：殺掉臨時 Hub。實際：把正式 Hub 也殺了——它的 port 來自 .env，
# 根本不在命令列裡
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -notmatch '8787' }
```

📌 **要殺的東西用白名單（明確 PID），不要用黑名單。** 那個條件描述的不是
「臨時 Hub」，而是「命令列裡沒有 8787 的東西」——包含了要保護的目標。
