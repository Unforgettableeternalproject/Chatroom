# Chatroom v1.2.8

v1.2.8：新增開發者模式、慶祝模式與通知中心，主持人可以用 override 處理所有管理操作，任務板的「未分類」改成可翻頁並能拆成獨立週期；上板流程改成在獨立 worktree 進行，並由專用 agent 收尾。內容涵蓋 v1.2.7 之後的所有變更。Hub、執行器、bridge 與 App 都有變更；資料庫資料版本由 7 升到 10，啟動時自動遷移。

## 新增

- **開發者模式**：開啟後，房間、任務、週期、訊息等各項 ID 會顯示出來，並可一鍵複製。房名與標題仍排在前面，ID 不會把名稱擠掉。
- **慶祝模式**：設定 > 個人化開啟後，成員加入、任務卡完成、派工房的派工成功時，從下方噴彩花並播放音效，觸發的系統訊息會金色呼吸一次。
- **通知中心**：App 右上角新增鈴鐺，集中顯示各類通知，主持人另有專屬的收件匣。原本任務板清單裡「我在等的東西」的入口移到這裡。
- **主持人模式 override**：主持人模式下，所有管理操作都可以 override，並且有「理由」欄位，操作理由會一併記錄。
- **未分類分頁**：
  - 任務板的「未分類」改成分頁，可以切換頁面；一頁完成後自動開下一頁。
  - 可以把未分類的任務拆成獨立的週期。
- **階段拖曳搬週期**：階段可以直接拖曳到別的週期，連同底下的任務一起搬過去。
- **回報點選跳轉**：在成員欄下方的回報清單點一份報告，聊天會同時跳到該派工 agent 的最後一則訊息（或對應的系統訊息）並呼吸高亮。
- **遠距預覽與「回到最新」**：跳到尚未載入或距最新超過 150 則的訊息時，不再往回載入整段歷史，改為顯示目標前後各 6 則的預覽（周圍模糊）；只要不在最底部就會出現「回到最新」按鈕，有新訊息時改顯示新訊息字樣。
- **派工收到佇列訊息先回 👀**：派工 agent 收到排隊中的訊息時，會先用 👀 表示已看到，再開始處理。

## 行為變更

- **上板改在獨立 worktree 進行**：不再動使用者目前的工作目錄，工作區有未提交的變更也照常上板。
- **合併方式**：上板由 ff_only 改成產生 merge commit。
- **專用 agent 收尾**：每次上板都會派一個專用 agent 收尾。遇到嚴重阻擋時，週期會被打回，並自動開出「上板阻擋」階段，列出要處理的項目。
- **沒有「重新上板」**：週期被打回後，處理完阻擋項目再重新送審即可。
- **上板記錄與結束週期**：有上板記錄的週期，必須上板成功才能結束；已結束的週期不能再上板。
- **舊上板紀錄不溯及既往**：升級前已經存在的上板紀錄會被標成舊紀錄，不套用新規則。
- **未分類頁**：未分類頁不能取消，也不能改名。
- **提及預覽**：提及預覽裡的群組改以中文顯示，並略去已被群組涵蓋的成員。

## 修正

- **離場事件名稱被截斷**：名字含空白的成員離場時，事件裡的名稱只剩空白前的部分；現在帶完整名稱。
- **認領衝突沒顯示持有者**：任務已被別人認領時，衝突提示現在會顯示目前的持有者。
- **表情選單灰暗**：修正表情反應選單顏色偏灰，以及尾端多出空白的問題。
- **釘選舊訊息跳轉沒反應**：點釘選的舊訊息現在會正確跳到該則訊息。
- **開發者模式房名被 ID 擠掉**：標題優先顯示，ID 排在後面。
- **已刪除房建立的階段底下建卡 500**：解除掛接且已刪除的房所建立的階段，在底下建卡會回 500；同類情形一併修正。
- **房主變更後封存請求殘留**：房主變更之後，舊房主發出的封存請求不再殘留。
- **Hub 安裝不更新既有排程設定**：重新安裝 Hub 時，既有的排程工作設定現在會同步更新。先前排程優先權過低，電腦忙碌時 Hub 啟動會很慢。

## 升級注意

- **資料庫遷移**：資料版本 `DATA_VERSION` 由 7 升到 10，Hub 第一次啟動會自動遷移，包含既有上板記錄的舊紀錄標記、通知資料表與未分類分頁。建議升級前先備份資料庫。
- **Hub、執行器與 App 要一起更新**：上板流程、通知中心、未分類分頁與階段搬週期都需要三者都是新版；舊 Hub 搭新 App 時，這些功能不會出現或會操作失敗，不影響其他功能。
- **agent 端介面變更**：objective 新增 `kind`、`page_no` 欄位；訊息新增 `run_id`；新增通知、`split_inbox`、階段 move、run `last_message` 等 API。agent 要等自己的 bridge 重新啟動才會用到；舊 bridge 照常運作。
- v1.2.5 起的 App 可以用「檢查更新」直接更新。
