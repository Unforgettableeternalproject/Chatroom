# Chatroom v1.2.6

v1.2.6：上板與派工前同步遇到分岔、衝突或推送被拒時，執行器會自己收斂並推上去，不必停下來等人處理；上板改用 SSH 簽章，失敗後可以重試。內容涵蓋 v1.2.5 之後的所有變更（含 v1.2.5-hotfix1）。Hub 有程式變更，資料庫版本不動。

## 新增

- **上板自動收斂**：上板遇到下列情況時，執行器會自己處理，不再直接失敗。
  - **本機穩定分支與 origin 不一致**：先把本機分支存成備份 ref `refs/runner-backup/<穩定分支>/<時間>`。本機獨有的內容都已在來源分支時，以 origin 重建本機穩定分支；否則以 origin 為基礎，把本機那一邊合併進來。
  - **來源分支本機與 origin 分岔**：合併 origin 後當上板來源，本機的來源分支不動。
  - **來源併進穩定分支時衝突**：起一支解衝突 agent，只解衝突並完成簽章 commit，不推送。執行器確認沒有衝突標記、parent 正確、有簽章之後才推送；確認不過就還原，以失敗收場。agent 沿用專案的工具白名單與網域，不另外放寬。
  - **推送被拒**（origin 在過程中前進）：合併 origin 後重推，最多 3 次；遠端 hook 擋下的不重試。

  上板結果會列出每個自主動作：重建、備份 ref、自動合併、agent 的 commit 與衝突檔案、推送重試次數。
- **派工前同步遇分岔時自動合併**：上一輪在本機 commit 但還沒推送、遠端又有新 commit 時，原本 `git pull --ff-only` 會失敗，整筆 run 以 `sync_not_fast_forward` 收場。現在會自動合併遠端，合併沿用執行器的簽章設定、不繞過 hooks。合併失敗時還原到合併前，照舊以失敗收場。收工摘要會寫明合併了幾顆、本機有幾顆未推送。
- **上板失敗後可以重試**：上板失敗後週期已是 verified，App 原本沒有任何地方能再上板。現在 verified／done 週期在沒上板過或上次沒成功時顯示「上板」，上次失敗另外標示「上次上板失敗」；上板成功或進行中不顯示。補上板不會改動週期狀態。
- **窄寬度任務板可切換週期**：寬度不到 900 時左欄收起，原本只能看預設週期；現在內容上方有切換列。

## 修正

- **上板合併失敗後沒有真正還原**：merge 卡在簽章逾時時，commit 可能已經產生，原本只做 `merge --abort`，收不掉這顆 commit，殘留在本機穩定分支，之後與 origin 分岔，往後的上板都在 pull 這一步失敗。現在一律退回合併前的 HEAD、清掉這一輪留下的未追蹤檔，確認無誤才切回原分支。
- **上板改用 SSH key 簽章**：`agent_signing_key` 原本只套用到派工 agent 的子進程，上板時執行器自己做的 merge／squash commit 與 annotated tag 仍走本機 GPG，人不在電腦前、passphrase 快取過期就卡在 pinentry，上板失敗。現在設了 `agent_signing_key` 時，上板產生的 commit 與 tag 也改用 SSH 簽章；沒設時行為不變。
- **重試能收斂**：推送失敗後重試，原本因為已經併過而判成「沒東西可併」，穩定分支永遠推不出去；現在會補推。tag 推送失敗後重試原本會卡在「tag 已存在」；現在 tag 指向同一顆 commit 時只補推。
- **上板狀態即時更新**：上板 run 轉態時推進週期的 `board_seq`，任務板會自動刷新，不必換頁才看到結果。
- **排程工作改用一般優先權**：工作排程器預設的低優先權會被整棵子進程樹繼承，機器忙時執行器的 `git fetch` 逾時、心跳中斷被判離線。`install-task.ps1` 與 `hub-service.ps1` 改用一般優先權。
- **`.env` 拒絕訊息改指向腳本載入設定**：原訊息讓 agent 以為連不上資料庫而放棄查證；investigate 模板允許跑完即刪的只讀查詢腳本。
- **熱修版 App 裝成正式版的 kit**：主機頁「安裝與更新」原本只查 `v<版本>` 的 Release，v1.2.5-hotfix1 的 App 仍顯示並安裝 v1.2.5 的 kit。現在熱修版會查 `v<版本>-hotfix<n>`，比對已安裝的 kit 版本時也忽略熱修序號，熱修版不會再永遠被判成不同版。

## 行為變更

- **本機穩定分支上的其他 commit 會一起推送**：v1.2.5-hotfix1 起，本機穩定分支有不屬於本週期上次失敗的未推 commit 時（例如手動 commit），會回報 `release_unpushed_unrelated` 並拒絕上板。這一版改成：內容已在來源分支的，視為冗餘並以 origin 重建；不在來源分支的，隨上板一起推送，並寫進結果。
- **解衝突 agent 的成本**：一個 repo 最多可能起 4 支解衝突 agent，每支各自計算預算與時限。

## 升級注意

- 要拿到上板與同步的修正，需重裝執行器；設定檔原樣保留，沒有新的設定鍵。
- 「上板」重試按鈕與窄寬度切換列需要換新版 App。v1.2.5 起的 App 可以用「檢查更新」直接更新。
- Hub 需要重裝才會推進上板週期的 `board_seq`；不重裝時任務板要換頁才看得到上板結果。資料庫版本不動。
