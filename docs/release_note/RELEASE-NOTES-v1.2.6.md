# Chatroom v1.2.6

上板自癒版。派工前同步與上板遇到分岔、衝突或推送被拒時，執行器會自己收斂並推上去，不再停下來等人處理。
Hub 沒有程式變更，資料庫版本不動。要拿到這一版的修正，只需要重裝執行器與 App。

---

## 執行器

- 派工前同步遇到分岔時自動合併：上一輪在本機 commit 但還沒推送、遠端又有新 commit 時，
  原本 `git pull --ff-only` 會失敗，整筆 run 以 `sync_not_fast_forward` 收場。現在會自動合併遠端。
  合併失敗時還原到合併前，照舊以失敗收場。
- 上板遇到以下情況會自動收斂：
  - 本機穩定分支與 origin 不一致：先存備份 ref `refs/runner-backup/<穩定分支>/<時間>`。
    本機獨有的內容都已在來源分支時，以 origin 重建本機穩定分支；否則以 origin 為基礎，把本機那一邊合併進來。
  - 來源分支本機與 origin 分岔：合併 origin 後當上板來源，不動本機的來源分支。
  - 來源併進穩定分支時衝突：起一支解衝突 agent，只解衝突並完成簽章 commit，不推送。
    執行器確認沒有衝突標記、parent 正確、有簽章之後才推送；確認不過就還原，以失敗收場。
  - 推送被拒（origin 在過程中前進）：合併 origin 後重推，最多 3 次。
- 上板結果會列出每個自主動作：重建、備份 ref、自動合併、agent 的 commit 與衝突檔案、推送重試次數。
- 修正上板合併失敗後沒有真正還原：merge 逾時時 commit 可能已經產生，原本只做 `merge --abort`，
  殘留的 merge commit 留在本機穩定分支，之後與 origin 分岔。現在一律退回合併前的 HEAD，
  清掉這一輪留下的未追蹤檔，確認無誤才切回原分支。

## App

- 修正熱修版 App 安裝到正式版的 kit：主機頁「安裝與更新」原本只查 `v<版本>` 的 Release，
  現在熱修版會查 `v<版本>-hotfix<n>`。比對已安裝的 kit 版本時忽略熱修序號，熱修版不會再永遠被判成不同版。

## 行為變更

- 本機穩定分支只領先 origin、而且內容不在來源分支時（例如有人手動 commit），原本拒絕上板，
  現在會隨上板一起推送，並寫進結果。
- 一個 repo 最多可能起 4 支解衝突 agent，每支各自計算預算與時限。

## 升級注意

- 執行器重裝後設定檔原樣保留，沒有新的設定鍵。
- 解衝突 agent 沿用專案設定的工具白名單與網域，不另外放寬。
