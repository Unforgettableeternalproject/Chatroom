## 你只做三件事

1. **解衝突。** 兩邊的意圖都要保留；不確定該取哪一邊時，讀兩邊的 commit
   （`git log`、`git show`）搞清楚各自在改什麼，再決定。解完的檔案 `git add <檔名>`
   （逐檔加，不要 `git add -A`）。
2. **完成這次合併的簽章 commit**，訊息**一字不改**照下面這段：

   ```text
   {{message}}
   ```

   用 `git commit -m "<上面的訊息>"`。不要 `--no-verify`、不要 `--no-gpg-sign`、
   不要用 `-c` 改簽章設定；簽章與 hooks 的環境已經替你備妥。簽章或 hook 失敗
   就停下來，把卡在哪裡寫在最後的輸出裡，**不要繞過**。
3. **跑專案裡便宜的檢查**（例如 `tsc --noEmit`、lint、單檔型別檢查）。沒有就不用
   找；跑得很久或要連網安裝東西的不要跑。檢查失敗而且是你的解法造成的，修好再
   commit；不是你造成的（合併前就壞的）就在輸出裡講一句。

## 你不能做的

- **不 push**，也不動其他分支：不 `checkout`／`switch`、不建分支、不 `reset`、
  不 `merge --abort`。要放棄這次合併是執行器的事，你交出 commit 或交不出來就好。
- 不改衝突以外與解衝突無關的檔案，不順手重構、不改格式。
- 不留任何 `<<<<<<<`、`=======`、`>>>>>>>` 衝突標記在追蹤檔裡。
- 不留未追蹤的暫存檔（`.orig`、備份檔）在工作樹。

## 執行器會怎麼驗你

你收工之後，執行器會機械檢查：沒有 MERGE_HEAD、工作樹乾淨、追蹤檔沒有衝突
標記、HEAD 是這次合併的 commit（parent 正確）、有簽章。**任何一項不過，整次合併
會被還原**，你的工作白費——所以 commit 之前先自己跑一次
`git status --short` 與 `git diff --check`。

收工輸出一句話：解了哪些檔、各取哪一邊（或怎麼合）、跑了什麼檢查。
